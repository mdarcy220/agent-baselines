# DSPy Prompt Optimization for ReAct Agent

This directory contains a DSPy-based prompt optimization system for the ReAct agent on the `astabench/sqa_dev` task.

## Overview

The DSPy integration optimizes the following prompts:
- **System Message**: The initial instructions that tell the agent how to use tools and submit answers
- **Continue Message**: The message urging the agent to continue when it doesn't make a tool call

### Architecture

The optimization pipeline follows this flow:

1. **DSPy generates candidate prompts** using GEPA or MIPROv2 optimizer
2. **For each candidate prompt**:
   - Create a solver with those prompts using `create_agent_with_dspy_prompts()`
   - Run `inspect_ai.eval()` with that solver on a specific sample (using `sample_id` parameter)
   - Extract the `global_avg` score from the evaluation results
   - Return the score to DSPy
3. **DSPy optimizes** based on per-sample scores across the training set
4. **Save optimized prompts** to JSON file

**Key insight**: DSPy only generates prompts; all agent execution and scoring happens through inspect_ai's framework, which ensures proper TaskState construction and task-specific tool provision.

## Files

- `dspy_agent.py`: DSPy signatures and helper functions for creating agents with custom prompts
- `optimize.py`: Main optimization script using GEPA/MIPROv2
- `optimized_agent.py`: Drop-in replacement for `basic_agent` that loads optimized prompts
- `evaluate_optimized.sh`: Script to compare baseline vs optimized agent performance
- `optimized_prompts.json`: Saved optimized prompts (generated by running optimization)

## Installation

1. Install the dspy extra:
```bash
uv pip install -e ".[dspy]"
```

2. Ensure you have your API keys set:
```bash
export OPENAI_API_KEY=...
export ASTA_TOOL_KEY=...  # For search tools in sqa_dev
```

## Usage

### Step 1: Run Optimization

Run the optimization script to generate optimized prompts:

```bash
# Basic usage (uses 20 train samples, 10 val samples)
python agent_baselines/solvers/react/optimize.py

# With custom parameters
python agent_baselines/solvers/react/optimize.py \
    --model openai/gpt-4o \
    --optimizer-model openai/gpt-4o-mini \
    --train-limit 50 \
    --val-limit 20 \
    --num-candidates 10 \
    --output optimized_prompts.json
```

**Parameters**:
- `--model`: Model to use for running the agent (the one being optimized)
- `--optimizer-model`: Model to use for DSPy optimization (generating candidate prompts). Can be cheaper/faster than agent model.
- `--train-limit`: Total number of samples to load (will be split into train/val)
- `--val-limit`: Maximum validation samples to use
- `--train-ratio`: Ratio of samples for training (default: 0.8)
- `--num-candidates`: Number of candidate prompts GEPA/MIPROv2 will generate
- `--output`: Output file for optimized prompts

**Note**: Optimization can be expensive! Each candidate prompt runs a full `inspect_ai.eval()` on each training sample. Start with small values (e.g., 5-10 train samples, 3 candidates) for testing.

### Step 2: Evaluate Optimized Agent

Compare the optimized agent against the baseline:

```bash
./agent_baselines/solvers/react/evaluate_optimized.sh --limit 10 --model openai/gpt-4o
```

This runs both agents on the same samples and saves logs for comparison.

### Step 3: Use Optimized Agent

Once you have optimized prompts, you can use the optimized agent in any evaluation:

```bash
# Using the optimized agent
uv run astabench eval \
    astabench/sqa_dev \
    --solver agent_baselines/solvers/react/optimized_agent.py@instantiated_optimized_agent \
    --model openai/gpt-4o \
    --limit 50 \
    -S with_search_tools=1 \
    -S with_report_editor=1

# Compare with baseline
uv run astabench eval \
    astabench/sqa_dev \
    --solver agent_baselines/solvers/react/basic_agent.py@instantiated_basic_agent \
    --model openai/gpt-4o \
    --limit 50 \
    -S with_search_tools=1 \
    -S with_report_editor=1
```

## How It Works

### DSPy Module (`dspy_agent.py`)

The `DSPyReActPrompts` module defines optimizable signatures:

```python
class SystemMessageSignature(dspy.Signature):
    """Generate a system message for a ReAct agent..."""
    task_description = dspy.InputField(...)
    submit_function_name = dspy.InputField(...)
    system_message = dspy.OutputField(...)

class ContinueMessageSignature(dspy.Signature):
    """Generate a message to urge the agent to continue..."""
    continue_message = dspy.OutputField(...)
```

### Metric Function (`optimize.py`)

The metric function bridges DSPy and inspect_ai:

```python
def metric(example, prediction, trace=None) -> float:
    # Extract candidate prompts from DSPy prediction
    system_message = prediction.system_message
    continue_message = prediction.continue_message
    sample_id = example.sample_id

    # Create solver with these prompts
    agent_solver = create_agent_with_dspy_prompts(
        system_message_text=system_message,
        continue_message_text=continue_message,
        ...
    )

    # Run inspect_ai.eval on just this sample
    logs = inspect_eval(
        tasks=[task],
        model=model_name,
        sample_id=sample_id,  # Only evaluate this specific sample!
    )

    # Extract global_avg score from the sample
    return logs[0].samples[0].scores[0].value["global_avg"]
```

### GEPA Optimizer

GEPA (Gradient-based Evolution for Prompt Adaptation) is a state-of-the-art optimizer that:
- Uses gradient-based search to explore the prompt space
- Generates multiple candidate prompts at each iteration
- Evaluates candidates on the training set
- Iteratively refines prompts based on scores

If GEPA is not available, the script falls back to MIPROv2.

## Tips

### Cost Management

Optimization can be expensive because each candidate runs full agent evaluations:
- **Start small**: Use 5-10 training samples, 3 candidates for initial testing
- **Use cheaper models for optimization**: Set `--optimizer-model` to a cheaper model (e.g., gpt-4o-mini) for generating candidate prompts, while keeping `--model` as your target agent model
- **Cache aggressively**: The `.dspy_cache` directory caches evaluation logs

### Training Set Size

For prompt optimization, you often don't need many examples:
- **5-10 samples**: Good for quick iteration and testing
- **20-30 samples**: Reasonable for production optimization
- **50+ samples**: Diminishing returns, but may help for very diverse tasks

### Validation

Always validate on held-out samples:
- Use `--train-ratio 0.8` to hold out 20% for validation
- Run the full evaluation script to compare on a larger test set
- Check that optimized prompts generalize beyond the training samples

## Troubleshooting

### `No global_avg found in scores`

The sqa_dev task uses multiple scorers that are aggregated. Make sure:
- You're using the full `sqa_dev()` task, not a modified version
- The task's scorer is configured correctly
- Check `eval_log.samples[0].scores` to see what scores are available

### Optimization takes too long

- Reduce `--train-limit` (fewer samples)
- Reduce `--num-candidates` (fewer candidates to try)
- Use `--optimizer-model` with a cheaper/faster model
- Check the `.dspy_cache` directory - logs might be growing large

### Import errors with GEPA

GEPA may not be available in all DSPy versions. The script automatically falls back to MIPROv2 if GEPA is not found. To use GEPA specifically, ensure you have the latest DSPy version:

```bash
uv pip install --upgrade dspy-ai
```
